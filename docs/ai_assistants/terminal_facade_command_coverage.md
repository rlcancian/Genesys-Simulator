# Terminal facade command coverage

This document tracks how `source/applications/terminal/GenesysShell` maps the public API of `source/kernel/simulator/SimulatorFacade.h` into shell commands.

The current shell uses `SimulatorFacade` as the main access point for safe CLI operations. Methods that require raw pointers, callbacks, template instantiation, or kernel-internal objects remain outside the direct CLI surface unless there is a clear textual contract.

Legend:

- `exposto` - reachable from the shell today.
- `alias` - legacy command name that forwards to a facade-backed implementation.
- `não exposto` - no direct CLI mapping today.
- `adiado` - plausible later CLI command, but not implemented yet because the textual contract is still unclear or the API is too low-level.

## Notes

- `model load` and `load` are still preserved as legacy aliases.
- `model save` and `save` are still preserved as legacy aliases.
- `simul`, `config`, `trace`, `plugin`, and `parse` remain legacy entry points that now route through `SimulatorFacade` where possible.
- `bash` remains a legacy escape hatch and still uses `system()`; it is not a model for new commands.
- `componentGetAllComponents()` is used internally by `component show/list`, but it is not surfaced as a raw standalone command.

## Follow-up candidates

- Add a text-safe `plugin check <file>` command if we want a direct shell wrapper for `pluginCheck()`.
- Add a read-only `plugin issues` command if we want to expose `getPluginLoadIssues()` diagnostics.
- Consider a future `model count/current/next/previous` extension if shell navigation of the model collection becomes useful.
- Keep `ParserManager`, `OnEventManager`, and pointer-based model editing APIs out of the shell until a stable CLI grammar exists.
