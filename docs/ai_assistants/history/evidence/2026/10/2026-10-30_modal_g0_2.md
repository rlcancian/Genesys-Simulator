cleanup could remove a valid EFSM Network and its states because specialized
Network/adapter relations were absent from `attachedData`. The focused
regression tests observed the Network, states, transitions, adapter reference,

The earlier fixture workaround also exposed a test-only segfault: adding an
adapter caused the fixture's graphical rebuild callback to enter
`ModelGraphicsScene::addGraphicalModelComponent` and then call
`PropertyEditorGenesys::addElement(this=0x0)`. GDB identified the null property
editor as the fault; no domain object had been deleted or used after free.
The persistence fixture now supplies a no-op graphical rebuild callback because
it tests the serializer/codec seam, not widget construction. The production
serializer still calls `model->check()` and the actual GUI target builds.

The localized production correction registers non-owning `attachedData`

states. `internalData` was not used, ownership was not transferred, and the
existing orphan policy still removes an unbound Network.

## Codec contract

The `.gui` section is `Graphical EFSM Network Diagrams`, schema version 1.
It stores Network identity, state IDs/positions, and optional transition
control/label positions. `EFSMTransition` has no persistent ID, so the codec
uses its global zero-based position in the transition list. This is safe under
the existing `.gen` contract because save and load iterate that list in the
same order. Source/destination and non-empty names are integrity checks;
invalid or stale references are dropped without modifying `.gen` topology or
mathematics. Unknown versions and malformed lines are ignored. Files without
the section remain compatible.
